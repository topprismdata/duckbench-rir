# 给 Coding Agent 的启动任务书（R0）

目标：将十四轮研究变成有证据、可复现、可逐步执行的科研闭环；不是立即建设训练平台。用户已同意 GPT 与 Agent 协同，不代表批准所有实验。

## 角色与权限
L0 用户：目标、预算、重大决策、训练/提交/部署授权。L-a GPT：研究方向、竞争假设、方法、独立审查及裁决。L-b Coding Agent：主动搜集原始资料、只读审计、独立复算、实现已批准的最小实验。L-c 可选独立复核者：盲评、重跑、挑战结论。Agent可以主动提出工作，不可自行扩大权限或宣称已通过GPT验收。

## R0：可并行启动的四项有界任务
|任务|工作|交付与验收|
|---|---|---|
|R0-1|官方DuckBench协议取证|版本、下载时间、SHA256、任务规则、观测动作、状态记忆、推理限制、评分/种子/提交条款；缺失明确BLOCKED；不提交策略|
|R0-2|Microduck官方、BAM、Microduck Lab只读审查|固定commit、许可、BOM、模型/执行器/观测/动作/控制时序、与DuckBench差异、现有基线、失败记录、Mac依赖；逐项证据路径，不改上游|
|R0-3|DeepMind Soccer原始数据复算|取得论文/补充/Zenodo数据及哈希，先审查Notebook，再用独立脚本复算Table1、Fig7可得数据；报告分母、排除样本、单位、误差；无数据即BLOCKED|
|R0-4|资源与研究缺口初审|读取本机硬件/软件版本（不安装依赖），审查P02–P05对照及反例，提出最小可证伪实验、预算与停止条件；不训练|

允许下载公开资料、只读代码调查、在独立工作目录编写并运行数据复算脚本。禁止未经批准安装系统级依赖、修改现有仓库、开始训练、提交竞赛、实体操作或上传私有数据。不得使用未审查的远程脚本直接执行。每项工作保留来源和失败记录。

## R1–R4（后续门禁，非当前授权）
R1：GPT审R0四份结果；锁定研究平台和已有资产；关闭接口/物理来源阻塞，决定是否允许最小环境探针。
R2：批准后复用现成基线，仅做接口 conformance、确定性回放、CPU性能分解和物理检查；禁止把烟测当训练成果。
R3：批准后最小对照：一个基础运动任务、直接策略与一种结构表示；同等观测、控制物理边界和预算，先短预算探索，冻结确认性协议后再正式训练。若效果无差异或成本高，停止复杂路线。
R4：批准后独立留出、非周期任务、负迁移与鲁棒测试；DuckBench只作外部评价，单独申请提交。

## 迭代纪律
每个工作包限定范围，先证据后实现；建议R0在一个短迭代内收口，具体时间与预算由用户/Agent确认，不承诺后台进度。每轮提交：目标、实际文件/commit、原始证据与哈希、复算命令/退出码、结果及失败、自审、未解决问题、下一轮最小动作。GPT只基于收到的可验证材料裁决 PASS / CONDITIONAL PASS / REJECT / BLOCKED。不得以口头自验或测试数量替代证据。

主动性要求：每轮先核对当前仓库事实（git log/status、manifest、台账），再恢复历史上下文；主动检索已有实现、反例及更简单替代；发现有价值方向写候选任务并说明收益、风险、验证法、成本；不等待用户逐条指出问题，也不擅自开工高风险任务。

## 首轮回执模板
- R0-1/2/3/4：状态、证据位置、实测与未测、阻塞
- 独立复算：输入sha256、脚本、命令、输出、差异
- 自审：至少一项反证或明确检索未发现；不得捏造
- 请求GPT裁决：逐项列出需要裁决的决策，不要求直接批准训练
