# C3 单次锁存设计（DESIGN ONLY）

> **R10 状态（GPT 裁决）**：设计保留为候选，执行未授权（新增训练 0 min、新增仿真 0 次）。本文件按 R10 意见修订，不再提交评审。

## 1. 问题

R7 的 C3 实现是**逐 tick 判断** height，而非批准的"单次锁存"，被判 PROTOCOL FAIL；原假设（状态触发调度可学）**NOT TESTED**。

## 2. 实现规格（先过门禁再训练）

```
CMD_LATCH = {"height": 0.15, "vx_before": 0.10, "vx_after": 0.19}
```

- 每个 episode 重置 `latched=False`；
- 每 tick：若 `not latched and z >= height` → `ctrl.vx = vx_after; latched=True`（之后**不再**读高度、不再改命令）；
- 每 episode 合法切换次数：**0（未达阈值）或 1（锁存）**；≥2 为实现失败，启动门禁 fail-fast；"未达阈值"不等于失败。

与 R7 的差异：R7 的 `CMD_SCHEDULE(mode="state")` 每 tick 重判，导致 5.5–6.4 万次抖动。

## 3. 设计

| 项 | 值 |
|---|---|
| 臂 | T0 固定 0.19、T1 episode 级随机化（同分布对照）、C3L 锁存（主要对照为 **C3L−T1**） |
| 种子 | 501–503 |
| 预算 | 3 × 3 × 5 min = **45 min**；总机时 ≤60 min |
| 评价 | 固定 0.19、固定 0.10、height 触发（V4 语义）、t=3 s 切换；best + last |
| 主指标 | V4 last 的全种子均值，C3L − T1 配对（主要对照） |
| 辅助 | 完赛率、互斥跌倒分类、切换次数（必须恰好 1）、切换后 1 s 行为 |

## 4. 评价的同构性

R7 指出 V4 评价程序在跌倒恢复后会重新进入 run，可能二次触发。本轮：

- 严格契约：episode 开始重置 latched；**节点重入不得重置**；恢复机制在对照间一致；恢复后可继续运动但不得发生第二次切换。
- 若现有 Host/program 无法表达该契约，登记 **BLOCKED**，不得自行修改 Host 或另造映射。
- 主指标：V4（height 触发）last 的全种子均值，C3L−T1 配对。

## 5. 判定

- C3L 在 V4 上优于 T1 且切换计数合法（0/1）→ 状态调度具备超越命令随机化的探索性证据；
- C3L 不优于 T1 → 未识别锁存机制额外收益（不是"无价值"）；
- 若出现 ≥2 次切换 → 实现失败，停止并修复，不解读结果。
