# T2′ 设计稿 — Episode 内时序命令调度（设计与文献，不训练）

依据 GPT R6.1 裁决：T2′ 优先开展文献研究与实验设计，不批准训练；T1 扩样暂缓；跨挑战迁移独立立项。

## 1. 未解决的问题（从 R6 继承）

| 阶段 | 训练时的命令暴露 | 结果 |
|---|---|---|
| T0 | 固定 vx 0.19 | 基准 6.600 s |
| T1 | **每个 episode 抽一次** vx∈[0.10,0.19] | 低速 7.750→6.707 s（−13.5 %），三 seed 同向 |
| T2 | 固定单次切换（height>0.15，0.10→0.19） | staged 6.823 s，与 T0 6.847 s 基本相同 |

T1 证明"命令**取值**分布"可学；T2 证明"一次固定切换"没有带来额外收益。**未验证**的是：episode 内多次、时刻未知的命令变化。

## 2. 机制约束（DuckBench 特有，决定可测空间）

1. 策略是 61 维输入的**前馈 MLP**（无记忆、无 recurrence），命令只出现在 `[48:55]` 的当前 tick 槽位。
2. 因此策略**无法预期**未来命令；它只能对当前命令做反应。任何"调度能力"只能是反应式的，或依赖**可观测状态**（如躯干高度）作为隐含上下文。
3. 高层的时序抽象在 DuckBench 里已存在：duckscript 以 10 Hz 做节点切换（相当于 options 的调度器）；本实验训练的是被调度的低层策略能否适配这种调度。
4. 不能给策略增加 mode/gait 输入槽（61 维契约固定），也不能提交 recurrent 策略 → 与文献中常见的 "gait-conditioned" 输入条件化不同，只能做**命令条件化**。

## 4. T2′ 候选设计（四臂，每臂 3 训练种子 × 5 min = 60 min，**待批准**）

| 臂 | 训练命令 | 目的 |
|---|---|---|
| C0 | 固定 0.19（=T0） | 同期基准 |
| C1 | episode 内**随机分段常数**：每 1–3 s 在 {0.10, 0.19} 间抽一次（期望 1–3 次切换） | 反应式调度适配 |
| C2 | **状态触发**调度：vx=0.10 当 height<0.15，否则 0.19（与 T2 同物理边界，但随机初始高度/相位） | 可观测上下文能否替代记忆 |
| C3 | **反向/冲突调度**：height<0.15 时 0.19，否则 0.10 | 控制"调度方向"，检测是否学到"高度→命令"关联 |

实现：env 增加 `CMD_SCHEDULE`（列表或状态函数），逐 tick 写 `ctrl.vx`；不改 Plant、不改 Host 实现、不改 obs 维度。逐 run 记录 `kit_diff.patch`。

## 5. 评价协议（所有臂同一套）

1. 固定 0.19；固定 0.10；
2. 单次切换（height>0.15，0.10→0.19）；
3. **未见过的切换时刻**（t=3 s / t=6 s 的时间触发，训练中未出现）；
4. 双向（0.19→0.10）；
5. 多次切换（0.10→0.19→0.10）。

指标：best-half、完赛率、切换后 0.5 s / 1 s 内跌倒、切换后达到命令速度的时间（追踪误差）、每 phase 位移、环境步数、loadavg、Actor 更新次数。

## 6. 可证伪的预测（先写死）

| 臂 | 若机制成立 | 若机制不成立 |
|---|---|---|
| C1 | 在未见切换时刻上优于 C0/T1 的零训练基线 | 与 C0 相同 → 说明反应式训练无迁移 |
| C2 | 在状态触发条件下最好，且对未见时刻也稳 | 只在训练相位有效 → 依赖具体轨迹 |
| C3 | 若学到"高度→命令"关联，应在反向条件上显著变差（负迁移） | 若无差异 → 说明策略只是跟随即时命令 |

## 7. 预算与风险

- 训练：4 臂 × 3 种子 × 5 min = **60 min**（请求上限 75 min，含 preflight 与评价）。
- 风险 1：命令切换会改变步态稳定性（R5.1 已见），可能大量冲线前跌倒 → 需按 phase 报告跌倒。
- 风险 2：无记忆策略可能物理上无法"预期"，C1 的收益上限有限；这正是要测的边界。
- 风险 3：切换时刻随机化会拉长 episode 状态分布，5 min 内可能欠拟合 → 与 T1 同样以 best/last 双报。
