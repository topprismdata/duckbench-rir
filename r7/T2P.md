# R7 / T2′ — Episode 内时序命令调度

问题（GPT 冻结）：在相同的命令取值分布下，训练中的**时序多样性**本身是否具有额外的学习价值？

## 4. 解释（探索性，n=3）

1. **复现了命令分布训练的价值**：C1/C2 相对 C0 在 V2–V7 全面更好（例如 V4：10.042 → 7.064/7.085；V7（last）：8.486 → 7.169/7.246）。C0 在 V1 与 C1 持平（6.960 vs 6.964），其余条件全面更差。
2. **时序多样性没有额外收益**：C2−C1 主指标 +0.08 s，三个种子方向不一致；V4/V6/V7 上 C2 与 C1 互有胜负（差异 ≤0.15 s）。
3. **状态触发（C3）** 与 C1/C2 同量级，但 V4（与其训练机制同构）反而 7.607 最差，V6 7.806——没有证据显示"高度→命令"关联被学到；且其训练暴露 18:82 严重偏斜，等于主要在 0.19 下训练。
4. 与 T1（连续区间抽样的 E2.1）一致：收益来自**命令取值分布**，不是时序结构。
5. **C3 协议判定 FAIL**（GPT）：批准的是"单次锁存"，实现是逐 tick 反复判断，两者控制语义不同；且评价程序 V4 在跌倒恢复后会重新进入 run，与 C3 的逐 tick 判断也不同构。原"与自身训练机制同构所以最差"的解释**撤回**；C3 的 V4（7.609）虽弱于 C1/C2，但仍优于 C0（10.042）。原单次状态调度假设登记为 **NOT TESTED**，不重训。
6. C1/C2 的实际低速暴露并非完全一致（54.2/52.6/52.9 % vs 50.6/50.4/50.0 %）→ 本轮支持"两种命令训练协议的整体比较"，不是隔离暴露量后的纯时序单变量因果。

## 5. 执行与异常

- 12/12 训练 `done`；无替换。
- C3 阈值抖动：每次越界都计一次切换（5.5–6.4 万次/run），等效高频命令噪声；这是设计缺陷，需在下一轮改为滞回（hysteresis）或一次性锁存。
- C3 暴露偏斜（18:82）使 C3 不能作为公平的"状态调度"臂。
- 评价程序 V5/V6/V7 的 t=3 s 切换在 timeline 中确认发生（`0 run(walk), 3.1 b(walk)`；V7 另见 6.1 s `c(walk)`）。
- 评价 168 次，全部 seeds 8–39。
