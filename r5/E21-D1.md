# E2.1-D1 — 命令接口诊断（零训练，≤10 min）

回答 GPT E2.1-D1 的五个问题。证据分三类：读码（Python 参考实现 + 官方卡片）、实测（TS 评价 JSON）、BLOCKED。

## D1-01 命令是否进入 Actor observation？

**是。**

- 观测布局（`kit/duckref/plant.py:251-262`）：`[48:51]` = twist，`[51:55]` = head_pose，二者来自 host 命令；`obs = concat(ang_vel, grav, joint_pos, joint_vel, prev_action, twist, head, body)`。
- walk host 的命令经速度映射进入这些槽：`steps-starter@1` 卡片 "follows (walk host): the walk node's vx … through the walk controller (speed map, start kick, heading hold)"，"trained at vx 0.19 … (vx 0.19 m/s = policy vx 0.4 after the speed map)"。
- 因此命令**不是**外部旁路，而是策略输入的一部分（被 host 缩放后）。

## D1-02 Host 在推理前还是推理后处理命令？

**推理前。**

- `duck_rl/env.py:377-389`：`_ctrl_for(node)` 每 tick 先算命令（walk 控制器或 raw block），然后 `duckref/bam.py:201-204`：`build_obs(policy, twist3, head_target4, body6)` → 取 `session(policy).run(obs)`。
- 顺序：host 命令 → 观测槽 → Actor 前向。TS 端按同一契约（`GUIDE.md`：walk 节点命令由 host 解释后送入策略）。

## D1-03 参数变化影响 Actor 输入、输出还是仅外部控制器？

**只影响输入槽（以及由此产生的动作），不改变权重。**

- 命令参数（vx/vy/wz/head_pitch）只写进 `[48:55]`；
- 同一个 move 文件在切换前后不变（见 D1-04 的哈希）；
- 实测：vx 0.10→有效速度 0.18 m/s，vx 0.19→0.49 m/s（切换后 2 s 均值），动作分布随之改变。

## D1-04 运行时切换命令是否改变 Actor 权重及 Normalizer？

**不改变。**

- P3 两个节点绑定同一个 `mv_e1c851c81055`（steps-starter@1），程序里没有第二份权重或归一化；simulate 只读该 move，训练/导出流程不参与（本轮零训练）。权重与 normalizer 的哈希见 `r1/SOURCE-REGISTRY.md` 与 cache 中的 move 文件。
- 但**内部状态会延续**（读码，Python 参考实现）：`plant.reset()` 只在 episode 开始调用；节点切换只重置 `_done_reset()` 的计数器/直立标志（`env.py:396-399`），不重置 `prev_action`（obs[34:48]）与 `head_cmd` EMA（`plant.py:222-256`）。→ 切换会在"上一动作 + 平滑头命令"未归零的情况下发生。
- TS 端是否同样延续：**BLOCKED**（无法从输出读取内部状态）；行为上 P3 切换后 1 s 内无跌倒（见 D1-05），与"状态延续但不致命"一致。

## 结论与对训练设计的影响

1. 命令是 Actor 输入（D1-01/D1-02）→ "命令条件化策略"这条路线在接口上是成立的，不是纯外部控制。
2. 命令切换不改变权重（D1-04），但可能携带 `prev_action`/EMA 状态；TS 侧无法验证，登记 BLOCKED。
3. P3 的收益（27 vs 26 完赛）伴随更差的均值与更多跌倒，尚不构成"调度优于静态"的证据（GPT 复算一致）。
4. 训练提案应明确区分两个问题：**命令分布鲁棒性**（训练时随机化命令）与**运行时调度收益**（固定命令表评价）；两者不得混为一个结论。
