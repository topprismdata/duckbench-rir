## 3. 解释（探索性，n=3）

1. **T1 得到命令鲁棒性**：固定 vx 0.10 下 7.7501 → 6.7071 s（−1.04 s，−13.4 %），完赛均值基本不变（31.7/32）；代价是标准命令 6.6003 → 6.7006 s（+0.10 s，+1.5 %）。这与"随机化训练使策略适应命令分布"一致。
2. **T2 没有显示阶段化收益**：staged 条件 6.8229 s vs T0 6.8471 s（几乎相同），完赛 29.0 vs 27.0；其固定 0.19 表现 6.7623 反而弱于 T0。按 GPT 纪律，不能据此宣称阶段命令训练有效。
3. **T1 也改善了 staged 条件**（27.0 → 31.0 完赛，6.8471 → 6.7182 s），说明命令分布训练覆盖了调度场景；但这与"调度本身的学习"混在一起，不能拆分归因。
4. 跌倒事件随训练上升（T0 35 → T1 59），与更快的前进速度一致；未发现切换后失稳（staged 条件的跌倒主要发生在全程爬升阶段）。

- 首次 staged 评价把策略只绑到 `run` 节点，切换后 `b` 节点退回库存走 → 全部 0/32（30 s）；修正为两节点同绑一个 move 后重跑，结果见上。该次错误评价的 JSON 已覆盖，事件记录在此。
- 训练环境的两处最小补丁（kit 内，逐 run 记录于 `kit_files.json`/`kit_diff.patch`）：
  1. `train.py`：允许 walk-stand 节点使用 `COMMAND_RANGES`（仅槽 0–2）；
