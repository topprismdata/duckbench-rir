# 奖励审计清单（通用第一步）

依据：K17（Hurdles 参考节奏 + 超前惩罚）、K19（Sprint fwd clip）。任何新赛事在训练前先跑这 6 项。

1. **速度上限**：奖励里是否有 `clip(|v|, …)`、`max(0, …)` 把有效速度截断？截断值是否低于冠军所需速度？
2. **参考节奏 / 超前惩罚**：是否有 `v_ref*t - x` 形式的“落后惩罚”同时惩罚领先？领先是否被错误扣分？
3. **时间窗**：训练 episode 长度与计分窗口是否一致（如 saucer 0–10 s、turntable 到 bell）？
4. **终止与惩罚**：fall/out 的惩罚是否远大于进步收益，导致策略保守？
5. **计分对齐**：奖励积分是否真的等于官方指标（best-half、rpm、turns），而不是代理量？
6. **实际生效值**：配置值 vs 运行时值（`--init` 覆盖 INIT_STD 这类，见 K01）；命令是否被 host 钳制（K04）。

判据：任一为“是/不清楚” → 先做 ≤10 min 的单变量消融，再谈加大预算。

已知案例：Hurdles（第 2 项，修复后 2.84→2.03）；Sprint（第 1 项，2.99→2.40）；Wheel/Saucer（6 项均过，仍平台 → 瓶颈不在奖励）。
